How it works

Check your archive before switching.

The audit compares the evidence. The signed migration report records the reviewed result.

  1. 01

    Inventory both folders

    Record file names, byte sizes, dates, album labels, edit warnings, and SHA-256 hashes.

    read
  2. 02

    Explain every difference

    Match exact file bytes. Name each missing item that your family accepts.

    compare
  3. 03

    Sign the migration report

    Record each device’s backup, deletion, conflict, and offline choices before switching from Google Photos.

    review

Run it locally

Start with one sample command.

The sample command creates its own temporary workspace and prints the report location.

terminal — local
cargo install --git https://github.com/B-Divyesh/sf-photo-exit-manifest
$ photo-exit-manifest demo
ready_for_cutover: /tmp/photo-exit-manifest-demo-…/migration-report

Reads Google export notes

The scanner reads the JSON file beside a photo and keeps album labels from duplicate copies.

Stops on missing decisions

Missing items, missing album labels, or unsafe retention settings keep the report on hold. Edited-looking files appear as warnings to review.

Works in scripts

Commands need no prompts. Add --json for machine-readable status and stable exit codes.

Privacy and limits

Your family controls every change.

The CLI does not move, edit, restore, or delete photos.

It does not send archive data over the network.

A ready report is evidence to review, not permission to delete your old cloud library.

Read the privacy policy or read the terms.
